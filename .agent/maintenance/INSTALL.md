# Встановлення та оновлення

Цей документ переноситься разом із `.agent/`; README продукту не потрібно замінювати.

## Нове репо

1. Перевір корінь цільового репо, наявні зміни й активні інструкції.
2. Скопіюй `.agent/`, тільки якщо такого каталогу немає. Кореневий `AGENTS.md` набору
   копіюй лише за відсутності місцевого файла. Інакше додай посилання на `.agent/AGENTS.md`
   до чинної точки входу, зберігши місцеві правила. Врахуй активний `AGENTS.override.md`.
   Не копіюй README набору поверх README продукту.
3. Адаптуй лише `project/` за manifest, конфігурацією перевірок, документацією й потрібним кодом.
   Запиши джерела фактів; рішення власника й дозволи не вигадуй. Незаповнений шаблон
   не блокує його адаптацію. Відсутню можливість познач із причиною.
4. Встанови `profile: project`, заповни поля та перевір конфлікти з місцевими правилами.
5. За наявності Python 3.10+ виконай із кореня цільового репо:

```text
python -B .agent/maintenance/validate.py --root . --mode project
```

Команда однакова для PowerShell і POSIX shell. Вона не запускає команди продукту,
не встановлює залежності й не перевіряє істинність записаних фактів.
Без Python виконай [ручну перевірку](../COMPLIANCE_CHECKLIST.md), зазначивши межі перевірки;
не встановлюй інструмент самовільно.
Перевір підключення в конкретному агенті, для Codex — за [адаптером](../adapters/CODEX.md).

## Оновлення

Для переходу 2.0 → 2.1 додай `profiles/ROLES.md` та онови точку входу й засоби перевірки.
Нові поля ролей і рев'ю необов'язкові: старий заповнений контекст зберігає типові значення.
Додавай конкретні умови рев'ю за потребою проєкту, не підставляй шаблон поверх його контексту.

1. Збережи попередній стан у Git або окремій копії, не включаючи чужі зміни у commit.
2. Порівняй версії та [історію](../CHANGELOG.md). Версія 2 змінює статуси, читання та формат контексту.
3. Онови погоджені файли ядра, адаптера й засобів перевірки. Не перезаписуй заповнений
   `project/` або місцеві інструкції шаблоном.
4. Перенеси факти старого контексту в нові поля зі збереженням джерел і заборон.
   Звір чинні вкладені правила в області робіт; набір їх не скасовує.
5. Виконай `--mode project` і ручну звірку правил. Збережи докази саме цього встановлення:
   звіт, що постачається з набором, описує перевірку його версії, а не цільового продукту.

Для відновлення поверни лише власні змінені файли з попереднього стану, зберігши пізніші
чужі зміни. Не застосовуй загальне очищення дерева. Автоматичний інсталятор і міграція
довільних старих форматів цим комплектом не надаються.
