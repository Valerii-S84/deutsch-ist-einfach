# Git-процес

- До першої зміни отримай актуальний `git status --short`, щоб відокремити власну роботу
  від наявних змін. Якщо актуальний результат уже відомий, не повторюй команду без причини.
- Додавай до індексу лише явно перевірені шляхи задачі. Не використовуй масове додавання,
  яке може включити чужі файли. Якщо індекс уже містить чужі зміни, не включай їх у свій commit.
- Commit роби лише коли його доручено або він передбачений погодженим процесом проєкту.
  Перед ним перевір відповідність вмісту індексу задачі та виконання потрібних перевірок.
- Формат повідомлення, гілки та merge-процес задає [контекст](../project/PROJECT_CONTEXT.md).
  Якщо формату немає, використовуй короткий опис зміни; не нав'язуй Conventional Commits.
- Не додавай агенту авторство коміту. Не переписуй історію і не змінюй чужий індекс самовільно.
- Push, PR та merge потребують окремого дозволу згідно з [безпекою](SECURITY_RULES.md).
  Не пуш безпосередньо у захищену гілку; невідомі параметри блокують відповідну публікацію.
- Успішний commit доводить створення коміту, але не чисте дерево. Якщо чистота є критерієм,
  перевір її після commit; інакше не запускай післякомітні перевірки за звичкою.
- Обсяг diff обирай за потрібним доказом. Назви файлів не доводять коректність вмісту;
  великий згенерований файл можна перевірити структурованим порівнянням потрібних полів.
