# Критерії завершення

До реалізації визнач спостережуваний результат і потрібний доказ. Для коду це релевантна
перевірка поведінки; для документа — відповідність запиту й узгодженість; для аналізу —
відповіді в погоджених межах із джерелами та явними невідомими. Не вигадуй команду тесту.

| Статус | Умова |
|---|---|
| `Done` | Усі погоджені критерії виконані та підтверджені; немає незакритої обов'язкової перевірки |
| `Partial` | Є корисний результат, але частина критеріїв, перевірок або потрібних дій не завершена |
| `Blocked` | Наступна необхідна дія неможлива без доступу, дозволу, даних або зміни зовнішніх умов |

Якщо зроблено частину і далі є блокер, звітуй `Partial` та назви блокер.
`BUDGET LIMIT` є причиною зупинки, а не четвертим статусом.

- Факт підтверджуй реально прочитаним джерелом, зміною, виводом чи іншим доказом.
  Висновок позначай як висновок; неперевірене — «потребує перевірки».
- Невдача обов'язкової перевірки або неможливість її виконати не дає `Done`.
  Згода прийняти ризик не робить тест успішним. Якщо користувач явно змінив критерії,
  оцінюй нові критерії та розкрий виключену перевірку й обмеження результату.
- Необов'язкова й нерелевантна перевірка не блокує завершення. Не створюй тести,
  що лише повторюють реалізацію, заради формальності.
- Наявні чужі зміни не забороняють завершити власну локальну задачу. Commit і чисте робоче
  дерево потрібні лише коли входять до погодженого результату; чужі зміни не прибирай.
- Перед звітом звір результат із критеріями та фактичними змінами. Повторні команди
  потрібні лише коли наявного доказу недостатньо для конкретного твердження.

## Статистика й адміністративні можливості

Зміна, що зачіпає адміністративні функції, потребує інвентаризації до/після, перевірки server-side доступу, API, даних і постумов дій. Повернення меню не є відновленням функції. Для кожної метрики потрібні джерело/продукт, формула, вікно/часова зона, фільтри, свіжість, правила дублікатів/пропусків та контрольний приклад. Нуль, відсутність даних, помилка й застарілість — різні стани. Невідомий контракт або відсутність backend-перевірки дає Partial/Blocked, а не Done.
