# Перевірка комплекту

Застосовуй під час встановлення, оновлення або зміни правил. Не запускай на кожному старті.
Це перевірка структури й узгодженості, не оцінка надійності моделі у відсотках.

1. Коренева точка входу посилається на `.agent/AGENTS.md`; активний override не приховує її.
2. Усі файли таблиці читання існують, локальні посилання ведуть до файлів цього комплекту.
3. Версія точки входу узгоджена з першим записом changelog.
4. Для бібліотеки шаблонів застосовано `--mode template`; для налаштованого репо — `--mode project`.
5. У робочому профілі немає незаповнених полів, прихованих варіантів маркерів або невідомих
   обов'язкових налаштувань; `не застосовується` містить причину. Перевірено джерела фактів.
6. Команди, стиль, середовища й Git-процес описують реальний проєкт, не вигаданий типовий стек.
7. Числовий бюджет має одиницю, межу, джерело та область обліку; або всі поля явно незастосовні.
8. Місцеві правила не суперечать ядру; немає подвійного нормативного визначення того самого правила.
9. Виконано відповідні [сценарії](maintenance/SCENARIOS.md); результат ручного розбору
   відокремлено від реального запуску агента.
10. За наявності умов окремого рев'ю визначено виконавця; роль не підміняє дозвіл
    на делегування, самоперевірку не названо незалежним аудитом.

Автоматична перевірка: команда в [інструкції](maintenance/INSTALL.md). Вона охоплює файли, посилання,
маркери, обов'язкові поля та форму бюджету; не доводить безпечність команд або істинність контексту.
Для ручної альтернативи перевір пункти вище та знайди всі входження `FILL_PER_PROJECT`
у файлах `project/`, незалежно від суфікса маркера. Не запускай інструменти цільового продукту
без потреби поточної задачі.
